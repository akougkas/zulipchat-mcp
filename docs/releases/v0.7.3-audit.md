# v0.7.3 release audit

Audit date: 2026-09-16. Baseline: `d5009f8` (`v0.7.3-beta.1`), including the
migration from stable `v0.7.2`. This document describes the prepared release;
publication is a separate step.

## Release and issue inventory

- GitHub and PyPI both identify **0.7.2** as the latest stable release.
- **0.7.3-beta** was published as a prerelease. **0.7.3-beta.1** exists as a Git
  tag and merged code, but has no corresponding GitHub release or PyPI artifact.
  Its draft-resolution and analytics fixes are carried into 0.7.3.
- No open pull requests were present. Community drafts work from
  [PR #15](https://github.com/akougkas/zulipchat-mcp/pull/15) and listener work from
  [PR #14](https://github.com/akougkas/zulipchat-mcp/pull/14) are retained. The
  listener still uses the contributed 90-second read timeout; the second pass
  disables the SDK's unlimited internal timeout retries so it can shut down.
- [#17](https://github.com/akougkas/zulipchat-mcp/issues/17), FastMCP final
  validation: addressed by FastMCP 4.0.4, real task execution tests, and the
  source/wheel protocol matrix. Close after publication.
- [#18](https://github.com/akougkas/zulipchat-mcp/issues/18), ping patch removal:
  addressed with a correction to its original premise. Upstream
  [python-sdk#3273](https://github.com/modelcontextprotocol/python-sdk/issues/3273)
  was closed as intentional behavior, not as a missing implementation to fix.
  Modern MCP does not expose ping. The patch and patch-specific tests are removed;
  legacy ping coverage remains. Close after publication with this explanation.
- The roadmap's stale “v0.6.0 (Next)” heading is replaced with unscheduled future
  work. Multi-organization support and catalog submissions remain future work.

## Confirmed findings and fixes

Severity reflects the impact under the deployment conditions in the description.

| Severity | Finding | Resolution and regression coverage |
| --- | --- | --- |
| Critical | `conditional_action` evaluated caller-controlled Python expressions with `eval`. Empty builtins do not prevent Python object traversal and code execution. | Replace evaluation with a bounded AST interpreter for data comparisons, boolean logic, indexing, dictionary lookup, and `len`. Tests reject attribute traversal, arbitrary calls, comprehensions, mutation, and unbounded arithmetic. |
| High | A message containing a request ID marked an approval answered before owner authorization, even outside the bound topic. | Authorize the sender and resolve the session first; only answer requests belonging to that session. Tests cover strangers, unrelated topics, cross-session IDs, and the valid owner. Remove the unbound legacy reply path, which has no verifiable owner/session binding. |
| High | Non-loopback HTTP startup warned about missing authentication but still exposed tools using the configured account. | Reject startup before config/database initialization without a non-empty token. Reject whitespace tokens and invalid ports. Real HTTP tests cover absent/wrong tokens, malicious Host/Origin, and successful discovery. |
| High | File downloads attached Zulip Basic credentials to arbitrary caller-supplied URLs. | Restrict authenticated requests to the configured origin and attachment path; reject traversal, credentials in URLs, scheme/port changes, and redirects. Tests verify rejected requests never create an HTTP client or write a destination. |
| High | HTTP callers could read/upload arbitrary server files or overwrite local paths through file tools. Callback URLs also exposed server-side network access. | Reject local paths and outbound callbacks for HTTP requests, including restored task HTTP headers. Keep these local capabilities available over stdio. |
| High | Crash “recovery” deleted DuckDB's write-ahead log after a lock holder exited, potentially discarding committed data. | Preserve the WAL and let DuckDB recover it on reconnect. Regression verifies the WAL bytes survive the retry path. |
| Medium | Runtime identity switching changed process-wide state for other HTTP callers. | Reject `switch_identity` over HTTP. Ordinary HTTP tools use the configured user; session tools retain their intentional bot identity. |
| Medium | Attachment deletion bypassed the advertised safe-mode boundary. | Require `--unsafe` before calling the deletion API. Regression proves safe mode makes no deletion request. |
| Medium | Local upload reads and HTTP download buffering could consume unbounded memory before validation. | Bound upload reads and stream downloads with a 25 MB limit. Tests verify failed/redirected downloads preserve existing destination files. |
| Medium | Filtering events before advancing their cursor replayed excluded events, while synchronous long polls blocked the MCP event loop. | Advance the cursor over all fetched events, run long polling in a worker thread, use a monotonic deadline, and validate listener bounds. Tests verify cursor progress and event-loop responsiveness. |
| Medium | Startup warmed caches with real Zulip requests, delaying startup and defeating the claimed offline smoke behavior. Invalid configuration exited successfully. | Leave caches lazy and exit nonzero on invalid config. Smoke uses isolated fake config files and temporary databases; startup regression verifies no client access. |
| Maintenance | Beta framework pin, protocol monkey patch, stale dependency lockfile, blank analytics model override, missing upload timeout, and ambiguous newest-wheel selection. | Upgrade and audit dependencies, remove the patch, retain documented analytics fallback, use a default for blank model overrides, add upload timeout, and select the exact normalized release wheel. |

## Second pass: source-wide review

The follow-up reviewed all **60 Python files under `src/zulipchat_mcp`**, including
modules outside the currently registered MCP tool paths. Review covered callers,
state transitions, SDK behavior, persistence, error handling, and existing tests.
This is a static-review scope statement, not a claim that every branch was run.

| Source scope | Files | Review focus |
| --- | ---: | --- |
| Package root (`__init__`, `server`, `config`, `claude_hooks`, `setup_wizard`) | 5 | Startup, transport/auth lifecycle, credential precedence, shell generation, permission-hook decisions |
| `core/`, including `commands/` and `validation/` | 23 | Account isolation, lazy SDK initialization, cache keys/expiry, approval/session state, retries/rate limiting, rollback, validation, provider integration |
| `tools/`, including registration and both tool tiers | 17 | All registered handlers, API request/response contracts, blocking calls, limits/pagination, safe-mode and HTTP restrictions |
| `services/` | 4 | Listener cursor durability, replay/shutdown behavior, registry persistence, scheduler account and recipient selection |
| `integrations/` | 3 | Generated local/remote commands, TOML escaping, Claude hook/package assets |
| `utils/` | 8 | DuckDB lifecycle and update semantics, logging/health, concurrent metrics, narrow/topic helpers |

Additional confirmed findings addressed in this pass:

| Impact | Finding and correction |
| --- | --- |
| Shell execution | Hook exports used JSON quoting in a shell context; `$()` and backticks could execute. Use shell quoting for exports and generated CLI arguments, and TOML-safe string encoding. Regression actually sources a hostile value in Bash and verifies it stays literal. |
| Wrong account / data exposure | The SDK reads credential environment variables ahead of a selected file. Resolve file credentials together before SDK construction; scope caches to the configured user/bot wrapper; prevent bot download credentials from falling back to the user. Exercise the real SDK constructor with only its network request mocked. |
| Approval ambiguity and races | Bare approvals selected the latest request, hook polls could consume another request's decision, and later replies/timeouts could overwrite terminal state. Require request IDs, update only pending rows, verify the stored hook decision, and keep polling timeouts resumable. Real temporary DuckDB tests cover immutable decisions and replay. |
| Session binding | Refreshing sessions regenerated topics and discarded project fields. Preserve bindings, serialize topic occupancy checks and writes within the process, reject occupied topics, distinguish long/truncated external IDs, and bound generated topic length with a stable hash suffix. A concurrent real-DuckDB regression checks that only one session can claim a topic. |
| Event loss and shutdown | The listener persisted a fetched batch's cursor before processing it. Persist after each successful event, deduplicate replayed event IDs, make state replacement atomic, and retain the old listener while it is stopping. Preserve events beyond the event tool's page cap. |
| Async responsiveness / duplicate writes | Many async tools performed synchronous SDK work on the MCP loop. Offload SDK operations and lazy initialization. Disable SDK automatic retries of ambiguous writes, and replace unlimited long-poll timeout retries with bounded calls. |
| Incorrect query results | Newest-first time searches fetched from the start of the interval, timestamp offsets were mislabeled as UTC, and timestamp narrows were plain text searches. Fetch from the requested end, normalize UTC, sort/limit results, and reject unsupported timestamp narrows with the supported search alternative. |
| False success | Searches, team analytics, scheduler batches, and upload-and-share flows could hide API failures. Preserve errors or explicit partial status and prevent failed searches from broadening to unrelated messages. |
| Incomplete operations | Mark-all/stream/topic-as-read processed one page; reaction metadata and some user/stream query options were ignored. Page until complete and forward advertised API arguments. |
| Reply attribution | Teleport replies could come from an old or unrelated conversation. Fetch only the chosen conversation after the sent message and exclude the sender's own messages. |
| Workflow and scheduler correctness | Workflow initializers required a dummy input; rollback could run twice and reaction rollback only logged a message. Initialize without input, remove reactions once on rollback, keep chain identity consistent, use scheduler-local credentials, and refuse partial recipient resolution. |
| Utilities and installers | Fix `uvx` command selection, empty-file handling, list-choice validation, mutable defaults, task-local temporary identities, bounded cache growth, concurrent rate-limit reservations, and valid escaped metric samples. |

The SDK contract review used the installed `zulip` implementation and Zulip's
[official OpenAPI definition](https://github.com/zulip/zulip/blob/main/zerver/openapi/zulip.yaml).
Regression tests were adjusted where the old tests explicitly encoded bugs
(ignored reaction metadata, private-only stream filtering, one-page completion,
and unsupported timestamp narrows). Network calls remain mocked.

## Protocol conclusions

The audit checked the published
[2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog),
[deprecated features registry](https://modelcontextprotocol.io/specification/2026-07-28/deprecated),
[HTTP transport requirements](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http),
and [Tasks extension](https://modelcontextprotocol.io/extensions/tasks/overview).

- Sampling is **deprecated**, not removed from the specification. Direct provider
  integration is the recommended migration. The existing server-side Anthropic
  implementation is retained and the documentation corrected.
- FastMCP 4.0.4 and MCP SDK/types 2.2.0 implement the protocol boundary. The project
  no longer modifies SDK method maps at import time.
- Modern tests cover discovery, tool listing and cache metadata, HTTP header/body
  mismatch rejection, tool calls, and SEP-2663 background task results. Legacy
  tests retain initialize/ping/tool calls. Core and extended tiers remain 20/60.
- Stateless requests do not make application state stateless. DuckDB sessions,
  approvals, event cursors, and default task storage are local. Independent DB
  paths do not support interchangeable replicas. Use one instance for these
  workflows; legacy HTTP connections may also use transport sessions.
- Static bearer authentication is a shared-account deployment mechanism, not
  per-user OAuth or tenant isolation. Use separate instances for unrelated
  accounts and a TLS reverse proxy for remote deployments.

## Upgrade notes and remaining limits

- Approvals now require `/approve REQUEST_ID` or `/deny REQUEST_ID`; recreate
  an old prompt if its instructions only say `approve`/`deny`. Polling timeouts
  do not expire requests, while permission-hook deadlines still deny on timeout.
- Selected zuliprc credentials override ambient email/key/site variables.
  Restart after modifying credentials because clients and account-local caches
  are now reused. Failed writes are not automatically retried; verify whether
  Zulip accepted a send before resubmitting it.
- Time-filtered searches return bounded samples, not exhaustive exports. Date
  anchors need Zulip 12 / feature level 445 for upper-bound queries and
  oldest-first queries with a lower bound. `relevance` is currently newest-first.
  Timestamp narrow helper calls now fail explicitly instead of silently searching
  message text. Use `search_messages` for timestamps.
- Generated session topics use a conservative 60-character maximum; existing
  session bindings are preserved. Custom server limits below that, cross-process
  session-creation races, and concurrent independent DuckDB writers are outside
  the supported single-instance deployment model.
- Utility metrics expose bounded recent-sample statistics as gauges, not
  cumulative Prometheus histograms. No HTTP metrics endpoint is added.

- HTTP users must configure a token on public binds and allow their actual
  hostname with `--allowed-host`. Add trusted browser origins explicitly when
  needed. HTTP filesystem paths, callbacks, and identity switching now fail
  explicitly; use stdio for those local workflows.
- Authenticated file downloads intentionally do not follow redirects. For
  externally hosted or redirected attachments, obtain the URL and open it in an
  authenticated browser. No cross-origin allowlist is silently inferred.
- Legacy unbound input requests must be recreated through the session model.
  Existing session-bound requests retain their storage format.
- Live Zulip integration and Anthropic generation were not exercised; the three
  opt-in live tests remain skipped. No chat messages or issue comments were sent.
- A scanner result is limited to its rules and advisory database. This work does
  not establish exhaustive absence of defects, complete MCP conformance, or
  multi-tenant safety.
- No release/tag was published as part of the local audit. Review the prepared
  changes and artifacts, then follow `RELEASING.md` to publish 0.7.3 and notify
  reporters with the existing community credits.
