## Install-instruction disclosure

The private Presend report describes a valid distribution-selection problem.
`uvx` infers a distribution from the executable name unless `--from` selects
the owning package. The hook, setup, and integration executables belong to
`zulipchat-mcp`; they are not separate packages. An inferred companion package
can fail today and expose arguments to a malicious package if that name is
registered later. The pasted message establishes the technical claim, not the
sender's identity or any actual exploitation.

All affected README/Claude examples now explicitly select the distribution.
Preflight and CI reject unsafe companion shell commands and JSON command/args
templates. Installed-wheel smoke also resolves each companion through
`uvx --from` with the wheel itself as the source. No placeholder package names
were registered. Previously published PyPI README metadata stays unchanged until
an authorized release publishes the corrected README.

## Architectural judgment

Retain FastMCP, the compact 20-tool default surface, the 60-tool extended surface,
optional background tasks, lazy Zulip clients/caches, separate user/bot clients,
and the shared coordinator. Concentrate this version on credential, persistence,
recovery, upstream API, and host-integration contracts. Do not replace the
framework or introduce runtime organization switching as part of this release.

The implementation now has an immutable resolved-account object, explicit
listener readiness/recovery, checked persistence outcomes, shared flag
pagination, and a dependency-light packaged-content loader. Named organization
profiles remain a [documented next design](../developer-guide/organization-profiles.md).

## Astra review resolution

A separate GPT-6-Astra Codex pane reviewed the baseline, preserved community
commit, and working tree. Its first report ranked 13 concrete findings. Its
second report identified seven follow-up gaps. Its final read-only pass found
**no remaining concrete blocker in those specific fixes** and independently
passed 26 targeted regressions plus isolated startup, pagination, and
dependency-light import probes. This is a scoped review result, not a guarantee
that no other defects exist.

A final bounded implementation pass also addressed the original recommendation
to retain one client throughout compound stdio operations. Task-local binding
now covers event registration/polling/cleanup, analytics data collection, and
flag resolution/pagination. Sixteen concurrency regressions switch identity
between phases, confirm independent operations use the newly selected identity,
and verify cleanup/restoration after cancellation and nested exceptions. Astra
passed 231 related tests and confirmed all 16 affected public async tool
signatures and return annotations remained unchanged.

| Original finding | Implemented resolution and meaningful checks |
| --- | --- |
| Environment bot key routed to ambient realm | Resolve the selected user's effective realm; exercise conflicting ambient site through the mocked SDK constructor and preserve explicit separate-bot realms. |
| Same-account owner replies discarded | Accept owner messages; suppress outbound IDs and documented SDK client attribution. Test human replies, exactly-once handling, same-process echoes, and the separate-hook-process persistence gap. |
| Prompt-before-listener and expired-queue loss | Require readiness before new prompts; register replacement queue before message backfill; persist session cursors and deduplicate overlap. Test immediate replies, expired queues, registration failure, replay, and same-second creation timestamps. |
| Old Claude credential hooks retained | Recognize exporter-owned hooks and replace their binding with `--force`. Test changed user/bot files, idempotency, preservation of unrelated hooks, and absence of old executable bindings. |
| Database reused across accounts | Fingerprint effective realms/principals, account-scope default paths, reject mismatched explicit paths, and require deliberate legacy association. Test realm/bot changes, restarts, and failed candidate cleanup. |
| Question reply syntax missing | Advertise `/reply REQUEST_ID answer`, preserve multiline text, and require correct request/session/type correlation. |
| Registered flag tool only handles one page | Use shared pagination for the actual registered tool; correct starring anchors and return partial progress on later failure. |
| Owner feed contains audit entries and loses acknowledged deliveries | Default to authorized inbound control events; add explicit audit access and opt-in scoped acknowledgements. Test mixed contents, dropped-response replay, and cross-session acknowledgement attempts. |
| Lifecycle persistence failures reported as success | Check mutations; distinguish an unsent operation from sent-but-unrecorded partial delivery and retain IDs. |
| HTTP cannot express arbitrary binary uploads | Add strict bounded base64 input and exercise NUL/non-UTF-8 bytes, malformed encoding, empty input, limits, and text compatibility through a real MCP call. |
| Cross-post forwards rendered HTML | Request raw Markdown and retain one client across the operation. Test source request parameters, formatted content, and partial destination failures. |
| Event observation hides poll failures | Preserve backend codes, bound retries, report errors/partial events, and clean up queues. Test persistent failure, recovery, collected-event failure, and cancellation. |
| Clio wait timeout disagrees with server wait | Export the real Clio timeout schema and teach every portable skill bounded 30-second waits with the same request ID. Test resumed waits and the actual Clio client. |

The seven follow-up fixes are included above: generic binding failures are fatal
and poison database access until successful explicit initialization; Zulip's
integer-second precision is respected; storage reads propagate failures; SDK
attribution covers the process boundary; explicit acknowledgements respect
scope; persisted local results bypass remote readiness; and Claude hooks poll
valid delivered partial requests. Hook permission polling also pages forward
from its request message rather than looking at only the newest 50 messages.

Analytics now report data fetched versus excerpts supplied to the provider and
truncation. Unrelated messages are not added to legacy listener storage through
the no-session path. Skill loading no longer imports FastMCP into exporters.

## API and live-integration follow-up

The complete current Zulip OpenAPI, real-time events and rate-limit headers were
reviewed against the installed SDK and registered tools. The
[operation inventory](../developer-guide/zulip-api-coverage.json) covers 163 REST
operations and three documentation references: 42 operations are reachable
through registered tools, 11 have internal wrappers only, one is SDK bootstrap,
and 109 remain unexposed. This is a curated proxy, not unrestricted REST access
or certification of every parameter. The [API contract](../developer-guide/zulip-api-proxy.md)
records scope, freshness, retention, retry and host-ownership limits.

That comparison fixed numeric stream lookup, subscription-property update
method and topic-mute fallback path. Requested optional stream-detail failures
now report partial results. Backend error codes/retry delays survive the MCP
boundary; application errors set MCP `isError`. Full and read-only discovery
match enforced policy. Pending response waits remain resumable without appearing
as failed deliveries. Search reports UTC dates, actual sample/excerpt coverage
and snapshot provenance.

Private identity-scoped message snapshots reuse successful reads for 15 seconds,
coalesce concurrent requests and invalidate on mutations/events. SDK requests
share a bounded principal budget, respect official rate headers/cooldowns and
disable transparent retries. The Generic-bot mention mode uses a durable local
inbox, scoped blocking events, bounded backfill and an OS producer lease.
Repeated host polls do not repeatedly fetch message history. Restart verifies
the bot's numeric ID. These safeguards have fake clock, concurrency, persistence,
recovery and actual registered-tool regressions.

The visible Luna demo completed four owner mentions with one bot post each in
the source topic. The final-wheel catch-up used one bounded message GET, no
detail reads and one result post, with correct UTC dates/IDs and explicit sample
limits. Its private host adapter corrected ambiguous Herdr delivery
metadata and per-message external-session IDs; the MCP correctly rejected the
conflicting second binding before any send. Stable topic sessions and task
deduplication IDs are now distinct in the skills. These are demonstrated host
integration corrections, not a claim of a new shipped Clio defect or production
unattended execution. Source/result ledgers and institution message bodies stay
outside the repository.

## Protocol and host contracts

The latest published MCP specification reviewed is
[2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/changelog).
The draft changelog inspected adds no newer published protocol to target.
Sampling remains deprecated; the existing direct Anthropic provider and
no-key data-summary fallback are retained. No protocol monkey patch is added.
The existing [Tasks extension](https://modelcontextprotocol.io/extensions/tasks/overview)
remains opt-in for the existing long-running tools.

New [SEP-2640 Skills](https://modelcontextprotocol.io/extensions/skills) support
uses the framework extension API. Modern responses include complete entries,
full frontmatter, `ttlMs`, `cacheScope`, exact UTF-8 resource sizes, and SHA-256
digests. All four skills remain ordinary Resources on legacy connections.
Manifest hashes establish content integrity, not publisher trust.

The canonical skills follow [Agent Skills](https://agentskills.io/specification).
Portable plugins follow [Agent Plugins 1.0.0](https://agent-plugins.org/) and
validate against vendored copies of its published schemas for offline tests.
Claude's native plugin remains separate. Native configuration exports target
Claude Code, Codex, OpenCode, Copilot CLI/VS Code, Antigravity CLI, Clio Coder,
and generic clients. Exported files do not change host trust, enable scheduling,
grant permissions, or publish a marketplace listing.

Clio validation uses `/home/akougkas/iowarp/clio-coder` v0.6.2-rc.3's actual
configuration parser, plugin validator, and stdio client. The client negotiates
MCP 2025-06-18, discovers all 60 tools, reads `server_info`, and creates a local
agent profile/session using fake credentials. The generated native YAML has
`version: 1`, a server list, and `timeoutMs: 900000`. Plugin content does not
cause Clio's loader to execute `mcp.json`; native MCP declaration/trust is still
required. No Clio files or trust records are changed by these checks.

Other host exports are tested for formats, schemas, preserved settings, conflict
handling, and packaged content. Their applications were not launched end to
end. Antigravity CLI's MCP fragment is explicitly staged for operator merge;
no unsupported project-autoload behavior or portable-plugin installer is claimed.

## Migration and remaining release work

Existing unbound databases are deliberately not adopted automatically. To retain
verified old sessions, set `ZULIPCHAT_DB_PATH` to the legacy file and pass
`--associate-existing-db` once; the flag alone selects the new account-scoped
default path. A bound fingerprint mismatch is always rejected. See
[the full migration instructions](../user-guide/configuration.md#persistent-state-and-account-migration).

Automatic event acknowledgement remains the compatibility default; agents that
need reliable replay must opt into explicit scoped acknowledgements. Individual
export writes are atomic, but a multi-file I/O failure may leave a partial export.
Sessions, cursors, and task state still require a single instance. Static HTTP
Bearer authentication is a shared-account deployment mechanism, not per-user
OAuth or tenant isolation.

After this local preparation, publishing remains a separate authorized task:
push/review/merge the branch, preserve contributor credit, authorize the tag and
release, let trusted publishing upload artifacts, verify installed release
metadata, and notify contributors/reporters with the actual release URL. No
communication should say 0.7.4 is available on PyPI before that happens.
