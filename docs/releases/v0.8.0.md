# ZulipChat MCP v0.8.0

Release date: 2026-11-08. Checked against Clio Coder 0.7.0 (MCP 2026-07-28) and
battle-tested on a real Zulip organization through Clio with a local model.

## Highlights

- **Clio Coder 0.7 support.** Exports declare per-tool `toolActionClasses`
  (`read`, `destructive`, `execute`). `--tool-profile read-only` exports a
  read-only declaration, and `--ephemeral-state` lets sandboxed read-only workers
  start the server without a writable account database.
- **Results that fit client budgets.** By default, `get_streams` and `get_users`
  return compact summaries; pass `verbose=True` to get the raw objects.
  `search_messages` and `get_message` accept `content_format="markdown"`.
  `search_messages` returns `sample.next_cursor` and `sample.completeness` for
  cursor paging, and puts this metadata before `messages`, so a truncated
  result still shows the paging state.
- **Task-augmented calls work.** `wait_for_response`, `listen_events` and
  `teleport_chat` no longer fail with `-32603` when a client declares the MCP
  Tasks extension.

## Behavior change

`get_streams` and `get_users` return compact summaries by default, and the
compact user summary omits `delivery_email`. Pass `verbose=True` to get the
previous output.

## Other fixes

- An invalid `after_time` or `before_time` now produces an error that names the
  parameter and the expected ISO 8601 form.
- An account database that cannot be opened for a reason other than a lock is
  no longer reported as locked.
- `get_stream_topics` accepts `stream_name`.

## Known issue (Clio Coder, not this package)

Clio's task-board reminder can tell the model to call `tasks` when
`--allow-tools` omits it, which makes the model loop until tools are disabled.
Include `tasks` in `--allow-tools`, or avoid numbered multi-step instructions in
restricted runs.

## Upgrade

```bash
uvx --refresh-package zulipchat-mcp zulipchat-mcp --version
```
